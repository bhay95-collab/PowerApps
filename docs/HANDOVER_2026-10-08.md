## 0. How to work with me (Ben)

- **Style:** short and direct. No filler. Give code when asked for code; explain only if asked.
- **I am new to coding.** Every instruction must be exact numbered steps: which screen, which control, which property, what to paste, what to click.
- **Ask, don't guess.** If anything is unclear, ask (use the multiple-choice question tool for decisions).
- **Push back** when an idea can be improved, but only when it matters to the purpose of the task.
- **Deliver code as:** a GitHub link to the file (I click **Raw** and copy everything), or the full code in chat if I ask. For small fixes, give only the changed property (control name → property → formula).
- **Before I paste a replacement screen:** tell me to delete the old screen first, add a blank screen, rename it exactly, then right-click → **Paste code**. If the old screen still exists, Studio adds `_1` to every control name, or I end up seeing the old screen.
- **After adding a SharePoint column:** tell me to refresh the data source in Studio (Data → list → ⋯ → Refresh).
- **Repo hygiene:** commit and push to the working branch. Never put staff/patient data exports in the repo.

### 3.2 Font and header art
- `AppFont = Font.'Segoe UI'` on every control.
- `HeaderImage`: an SVG data URI with a navy → teal → bright teal horizontal gradient (`#001D46 → #075F73 → #00838A`). It is used as an Image filling every header container (`ImagePosition.Fill`) on top of the `RGBA(7,95,115,1)` fill. Exact formula: `powerapps/dtv/App_Formulas_additions.txt`.
- App icon: white symbol on a diagonal navy → teal gradient, with the symbol inside the middle 70% so masks never clip it (`powerapps/icon/`). Prompt for generating new icons is in the chat history; the style is "flat white line icon, rounded strokes, gradient #001D46 → #075F73 → #00A3A8, faint top-right glow, no text".

### 3.3 Sizing systems (the screen-size maths differs per app)

**Mobile and DTV apps** (App > Formulas):
```
UI     = Max(0.9, Min(1.25, Min(App.Width, App.Height * 0.55) / 390));  // scale factor
PageW  = Min(App.Width, 720);                                           // content column width
Gutter = (App.Width - PageW) / 2;                                       // side space on tablets
SheetW = Min(App.Width, 600);                                           // pop-up sheet width
```
Every size is written `Round(n * UI, 0)`. Content width is `PageW - Round(40 * UI, 0)`; body padding is `Gutter + Round(20 * UI, 0)` on each side. Settings → Display: Scale to fit **Off**, Lock aspect ratio **Off**, portrait.

**Desktop app** (drawn for 1366 × 768, then stretched):
```
SX = App.Width / 1366;  SY = App.Height / 768;
SF = Max(0.75, Min(1.4, Min(SX, SY)));   // text
SR = Min(SX, SY);                        // radii and gaps
```
X/Width use `* SX`, Y/Height use `* SY`, text `Round(size * SF, 0)`, radii `* SR`. `tools/make_responsive.py` converts a fixed screen. Studio omits default values from exports, so the script writes the defaults back before scaling.

**Training stand-alone:** `Wide = App.Width >= 820` (two columns, list + detail), `PageW = Min(App.Width, 1280)`, plus `GapPx`, `ListW`, `DetailX`, `DetailW`.

### 3.4 Font sizes are POINTS, not pixels
Power Apps `Size` is in points (1 pt = 1.33 px). Designs drawn in px must be converted, or everything gets cut off with "…" on a phone.
Mapping used (px design → pt Size): 36→28, 24→19, 22→18, 19→15, 18→14, 17→14, 16→13, 15→12, 14→11, 13→11. Minimum readable size is 11 pt.

### 3.5 Screen anatomy (mobile / DTV)
```
Screen (Fill C_Bg)
└ conRoot_X        GroupContainer AutoLayout, vertical, Stretch, Height Parent.Height
  ├ conHdr_X       ManualLayout, FillPortions 0, Width App.Width, header teal + imgHdr_X (HeaderImage)
  ├ conBody_X      AutoLayout vertical, gap 12–15*UI, padding Gutter+20*UI, LayoutOverflowY Scroll
  │  ├ cards…      FillPortions 0, Height = LayoutMinHeight = Round(n*UI,0), Width PageW-40*UI
  │  ├ gallery     (no FillPortions → fills the remaining height, scrolls itself)
  │  └ conEnd_X    16*UI spacer as the LAST child (a scrolling container ignores bottom padding)
  └ conFoot_X      optional sticky bottom bar (white, 84*UI) holding the main action
```
- **Home header:** 165 high. Kicker in caps (11 pt bold, white 80%), title (28 pt), "Hi <first name> · <day date>" line.
- **Sub-screen header:** 95 high. Back chevron as a ModernButton with `Icon: "ChevronLeft"` (60 × 60, Size 24 pt), title 19 pt at X = Gutter + 65*UI, subtitle 12 pt (step / context).
- **Cards:** white, `C_Line` border 1, radius 18–25*UI. Card padding is 18–22*UI.
- **Section captions:** UPPERCASE, 11 pt bold, `C_Muted` (e.g. "YOUR STREAM", "1 · LOGIN").
- **Hero action card:** solid `C_Accent`, radius 25, an icon in a translucent circle, a white title and subtitle, and a transparent button over the whole card.
- **Tiles:** a white card with an icon circle (`C_AccentSoft`, or `C_AmberBg` for amber actions), title and subtitle, and a chevron right at `Parent.Width - 38*UI`.
- **Gallery rows:** card width `Parent.TemplateWidth - 10*UI`, X = 1. Leave room for the scrollbar, or the right corners get clipped. Text width `Parent.Width - 56*UI`. Chevron at `Parent.Width - 36*UI`. TemplateSize is the row height plus 10.
- **Status stripe:** an 8 px bar on the left of a row (red = needs follow-up, green = clear).
- **Pills / segments:** height 48–50, radius = height / 2. Selected = `C_Accent` fill with white text. Unselected = white with a `C_Line` border and `C_Ink2` text.
- **Choice buttons** (single select, e.g. "Why not?"): stacked full-width pills 44 high. Selected = `C_AccentSoft` fill, `C_Accent` border and text.
- **Yes/No pairs:** two half-width pills with a 12*UI gap. Selected Yes turns green, selected No turns red.
- **Multi-select chips:** same as the choice pills, showing "✓  " before the text when selected. Stored in a collection.
- **Warnings:** amber card (`C_AmberBg`, border `RGBA(178,105,0,0.35)`, `C_Amber` text).
- **Progress bar:** track `C_Line` (8 high, radius 4), fill `C_Accent`, which turns green at 100%.
- **Empty state:** a centred muted label, visible when `CountRows(gallery.AllItems) = 0`.
- **Text:** Title Case on buttons, titles and labels ("Start an Audit", "Audit Another DTV"). Captions in CAPS. Keep wording short enough for one line on a 375-wide phone; shorten the text rather than wrap. Labels use `Wrap: false` unless they are made for 2 lines.

### 3.6 Interaction patterns (use these, not the alternatives)
- **Tap targets:** a transparent `ModernButton` (Appearance Transparent, Text "") laid over a styled container. It is the last child, so it sits on top.
- **No Classic ComboBox for people or patient pickers.** In these apps it shows a blank list until you type. Use a search box plus a gallery, or a pop-up list.
- **Prefer pills/chips over dropdowns** for short option lists. Use one row of equal-width pills and avoid horizontally scrolling chip rows (they cut text off). Derive short labels in a formula if the names are long.
- **Shared logic** lives in one hidden button (`Visible: false`, 1 × 1) that other controls call with `Select(btnX)`. One copy instead of many.
- **Cards that grow:** a container's `Height` and `LayoutMinHeight` use the same formula, e.g. `Round((If(varLogin = "No", 422, 140)) * UI, 0)`. The children that only show for that state have `Visible` set. Check every state's bottom edge against the height plus 18 px padding.
- **Form completeness** is written once (e.g. in the submit button's `DisplayMode`). Other controls refer to `btnSubmit.DisplayMode = DisplayMode.Edit`.
- **Sticky submit bar:** always visible. It is grey with "Answer every question to submit" until the form is valid.
- **Double-tap guard:** `Set(varSaving, true)` at the start of the save, include `!varSaving` in `DisplayMode`, and reset it on success, on failure and in `OnVisible`.
- **Confirm before destructive actions** (remove, delete, return).

### 3.7 Branded email template (all apps and flows)
- `EmailHead` / `EmailFoot` are named formulas (`powerapps/email/Email_Formulas.txt`). Build an email as: `Substitute(Substitute(EmailHead, "{{TITLE}}", t), "{{SUB}}", s) & <rows> & Substitute(EmailFoot, "{{NOTE}}", n)`.
- Look: a pale page background; a white 680-wide card with an 18 px radius; a **32 solid-colour table cells gradient bar** (navy → teal); a teal title block with the kicker "STARS PHYSIOTHERAPY", the title and the subtitle; a soft grey footer reading "Sent from the STARS Physiotherapy app by <name>".
- **Outlook desktop (Word engine) ignores CSS gradients and many border-radius rules.** That is why the bar is built from 32 coloured cells. Keep table-based HTML with `bgcolor` attributes and inline styles.
- Flows use the same HTML (built in the flow's Compose / Send email actions).

## 4. Power Fx and Studio rules learned the hard way

**Pasting / YAML**
- Delete the old screen before pasting its replacement. Control names are global, so a clash gives `_1` names, or you see the old screen.
- A formula containing `: ` or ` #`, or spanning several lines, must be a YAML block scalar (`Prop: |-` then the indented `=formula`).
- A formula that starts with a `//` comment exports as a quoted string. That is fine.
- Studio exports leave out default property values. If you add controls by hand, set Width, Height, Size and Font explicitly.
- Control versions that paste: `GroupContainer@1.5.0` (AutoLayout / ManualLayout), `Label@2.5.1`, `ModernButton@1.0.0`, `ModernIcon@1.1.1`, `Classic/TextInput@2.3.2`, `Gallery@2.15.0` (Vertical / Horizontal), `Image@2.2.3`, `AddMedia@2.2.1`, `BarcodeReader@1.0.25`.
- ModernIcon names known to work: `CheckmarkCircle`, `ChevronLeft`, `ChevronRight`, `AppsList`, `Search`, `Camera`, `ArrowClockwise`.
- After changing App.Formulas or OnVisible, run **Run OnVisible** (⋯ on the screen) in Studio to clear stale errors.

**Data**
- **Columns imported from Excel have internal names `field_N`.** `SortByColumns` and `ShowColumns` need the internal name (`"field_2"`, `"field_11"`). Filters and formulas accept display names. `ShowColumns(DTV_Register, Title, Stream)` broke `Stream`, so copy the whole list instead (`ClearCollect(col, DTV_Register)`).
- **Choice columns** read as `.Value` and are written as `{ Value: "x" }`. **Multi-select choice** is written as `ForAll(col As e, { Value: e.Value })`.
- Numbers vs text: `Coalesce` must get one type. Example: `If(IsBlank(x.Bed), "—", Text(x.Bed))`, because Bed is a number.
- **Blank is not 0.** `If(var = 0, …)` is false when `var` is blank, so `x / var` divides by zero. Work out ratios once into a variable (`If(n > 0, a / n, 0)`) and read them with `Coalesce(var, 0)`.
- **Stale records:** a Patch or With that uses a record read earlier can overwrite someone else's change. Re-read with LookUp right before checking a status (allocate / return). For swaps, capture both values first, then patch.
- **Check `Errors()`** after every Patch before writing log rows or showing success: `If(!IsEmpty(Errors(List)), Notify(...), ...)`.
- **Optimistic lock** (ward board): keep `Modified` when loading, and refuse to save if SharePoint's `Modified` is newer.
- **Caching:** Power Apps reuses its copy of a list. After saving, `Refresh(List)` before re-reading, and also update the local collection straight away (e.g. `Collect(colRecentAudits, { Value: tag })`).
- **Delegation:** `Lower(column)` and `in` are not delegable. SharePoint `=` is case-insensitive, so use `Email = MeEmail`. Date comparisons are delegable (`Created >= DateAdd(Now(), -1, TimeUnit.Months)`), but `DateDiff` on a column is not. Small lists (< 500) are fine to filter on the device.
- **SharePoint Image column:** patch the Image control's `.Image`, not the Add picture `.Media` (`.Media` gives a "Record expected, Text found" error). Template: `SetupImage: UploadedImage3.Image` in the Exercise app; `AuditPhoto: imgPhoto_Aud.Image` in DTV. Save the record first, then patch the photo, so a failed photo never loses the record.
- **Person columns:** `'Created By'.DisplayName`. SharePoint records Created / Created By automatically. Use those for who and when, never Modified.
- `Exit()` closes the whole app on a phone. Never use it for flow control.
- `DateValue(DatePicker.SelectedDate)` depends on the PC language. Use the date directly.
- Prefer `TimeUnit.Days` over `"Days"`.
- `Select()` works on hidden buttons on the same screen.

**Flows (Power Automate)**
- Distribute flows as **Import Package (Legacy)** zips (manifest.json, Microsoft.Flow/flows/manifest.json, flows/<guid>/definition.json, apisMap.json, connectionsMap.json). After import, open each step and re-pick the list from the dropdown if it is red. The connector stores **list GUIDs**, not names.
- The Power Apps trigger is `kind: PowerAppV2`. Inputs are named `text`, `text_1`, `number`, `file` (`{name, contentBytes}`).
- The SharePoint "Send an HTTP request" action (operationId `HttpRequest`, `parameters/method`, `parameters/uri`) works with `getbytitle('<exact list title>')`. List titles must be exact (`Equipment_Usage_Log`, not "Equipment Usage Log").
- Filter expressions inside actions must start with `@` or be built with `concat(...)`. A plain-text "concat(" is not evaluated.

## 8. DTV Audit app (`powerapps/dtv/`, generator `tools/dtv_generator/`)

**App.Formulas:** colours (no `C_Danger`), AppFont, HeaderImage, UI, PageW, Gutter (`App_Formulas_additions.txt`). `varStream` (the auditor's stream) is set elsewhere in the app (App.OnStart).

**Screens and flow**
1. **`Home`**
   - Header with the "ieMR DOWNTIME VIEWER AUDIT" kicker.
   - **Start an Audit:** your stream; all DTVs if you have none.
   - **Your Stream** card: "x of y audited", with a progress bar.
   - **All DTVs** tile: site-wide count and bar.
   - **Re-audit** tile.
   - OnVisible: resets `varStreamPick` and `varReaudit`, does `Refresh(Audit_Results)`, builds `colRecentAudits` (titles audited in the last month) and `colAllTags`, works out `varMyDTVs/Done/Pct` and `varAllDTVs/Done/Pct`.
2. **`SelectDTV`**
   - Search (department, location, asset, name).
